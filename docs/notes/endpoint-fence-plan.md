# Endpoint queue fence (#55)

Retain a transcribed endpoint candidate until Capture processes a fixed FIFO fence inserted after transcription. Frames already queued at insertion retain their original order; observed VAD resumption invalidates the old transcript and preserves its full audio for the next endpoint. The direct InputPipeline seam keeps its immediate mode; Capture uses deferred commitment. No endpoint threshold, silence fallback or model changes.

1. Reproduce gated STT plus timestamped queued continuation at the Capture seam, then cover one Hub Task from the retained complete request.
2. Add opaque candidate identity and deferred preparation/finalization to InputPipeline. Cache unchanged transcription, keep the opening, and log candidate/fence/invalidation/commit identifiers without text.
3. Serialize a fixed fence through Capture's existing queue. Reject stale capture/replacement/shutdown/overflow results; preserve source-callback AEC and bounded buffering.
4. Cover silence-only fixed fences, partial VAD windows, capture replacement, shutdown, overflow and genuinely post-fence speech. Document the boundary to #38.
5. Run focused regressions, full pytest and Pyright; commit and release the worktree lock.

## Implemented boundary and limits

Capture uses an opaque endpoint sequence for each transcription and a stable utterance candidate across revisions. It inserts one fence after STT under the same lock used to enqueue source frames. The captured-frame watermark describes that fixed position; later source frames cannot extend it. The capture worker processes all preceding frames, then compares the retained candidate's last observed speech with the transcription snapshot. A resumed utterance keeps its opening and is transcribed again only when the ordinary endpoint rule permits it. Unchanged speech reuses its prepared transcript. Direct synchronous InputPipeline callers retain immediate delivery.

Capture switches carry an epoch. Delivery checks that epoch again on the event loop for all owner-bound input events, including SpeechStarted, Heard, CaptureAborted and barge-in evidence. A switch queued while inference runs cannot publish those old events. Raw WakeWord remains subject to VoiceMode acceptance. Raw Wake word hits do not invalidate an active utterance: VoiceMode intentionally ignores them while the User is in a turn. Accepted capture ownership changes invalidate pending candidates through the capture epoch. Overflow drops the incomplete utterance and blocks new turns until an explicit capture switch or Wake word; inference failure does the same. An owned CaptureAborted event ends an abandoned active turn without admitting a request, restores the normal listening or Follow-up deadline, and reports how to retry after loss or the retention cap. Abort delivery uses the same capture-epoch check as Heard, so failure of an old capture cannot terminate its replacement. Shutdown discards pending input. AEC still runs on the source callback, and all VAD, endpoint and STT inference remains on the existing capture worker. Frames remain bounded by the existing queue cap; retained utterance audio is capped at the existing maximum-turn frame count plus the existing backlog frame count and one 10 ms rounding frame. Repeated resumption beyond that cap discards the incomplete candidate and blocks until rearmed, rather than growing audio through successive fences. The fence does not add a silence timeout or wait for an empty queue.

VAD evaluates complete windows only. The production 512-sample window is 32 ms at 16 kHz; a fence can occur with fewer than 512 samples buffered. Speech in that unfinished window has not been observed and cannot invalidate the prepared transcript. The regression uses an exactly aligned four-frame VAD to show both sides: one queued speech frame remains unobserved, while four frames invalidate the endpoint. There is no extra window padding or threshold change.

Synthetic tests hold STT while timestamped continuation frames queue, then verify one complete Hub request and one delegated Task. Typed requests arrive silently both during that hold and afterward. Other tests cover capture replacement, an ignored Wake hit inside an active utterance, shutdown, overflow, inference failure, repeated resumption at the retention cap and silence that continues arriving after the fixed fence. A separate test waits for the first commitment before starting new speech and gets two requests: the fence cannot recover a continuation that begins afterward. That case remains #38, and these tests do not establish the complete thinking-pause gate in #34. No native model, physical device or conversational backend was used for this change.

Diagnostics contain utterance/endpoint IDs, capture epoch, inserted/processed watermark, VAD speech time and invalidation/commit reason. They contain no transcript text. Existing turn metrics and optional local clips are written only for the final committed candidate.

Review regressions use the actual Capture, VoiceMode and Hub with fake agents: STT failure, overflow and the retained-audio cap release the active turn; silence reaches idle and a fresh Wake accepts a later request. No discarded transcript reaches the Talker or creates a Task. A raw detector hit queued with an in-turn continuation retains the opening and still delivers one request and Task, including when typed input arrives during STT.

A disable or replacement of active capture clears the old onset, unfinished VAD window and pre-roll as well as its turn. A fresh false-to-true enable preserves idle onset and pre-roll, so a Wake word and request in one breath still keep their opening. Stale-event tests cover both an accepted Wake interleaved at the AudioInput event seam during gated VAD, and the actual Capture FIFO path where a frame computes WakeWord before blocking in VAD. After the old listening deadline expires, the delayed Wake is accepted but its old SpeechStarted is rejected; silence still reaches idle. The FIFO test also verifies a later complete one-breath request, with no ghost request or piecemeal tail. Separate capture tests reject both a queued off/on replacement and a same-on replacement without recreating the old onset.
