# Cumulative directed stops

Ticket #72 integrates the guarded source, Follow-up, capture-fence and playback-drain lineage from PR #70 at `3e8a893048282a1645af6aec8047719de6aaad0c`. Current main `a184b10` is an ancestor and the integration has no textual conflicts. That lineage includes idle wake handoff support; it does not qualify wake recognition. ADR 0018 supplies the new cumulative policy.

Opt in with `JARVIS_ADMISSION_BACKEND=jev` and `TYPESAFE_API_KEY` in `.env` or the process environment. The key is omitted from settings representations. Start without a key to see explicit setup status; configuring a key is not proof of provider readiness. The existing explicit `claude` setting retains its older endpoint-only path. Selecting Jev never selects another provider as fallback. Text-only mode constructs neither assessor.

The audio adapter transcribes the same captured source repeatedly at most once per 400 ms while speech advances. These are repeated batch calls on the existing inference thread, not native streaming. A hypothesis replaces its predecessor using source identity and revision. Final endpoint transcription replaces partial words before submission. Pauses carry observed boundaries and snapshots include elapsed silence, preceding request ownership, phase and bounded played text with a queue-estimate basis. This is not physical hearing evidence. AEC still processes frames before the bounded inference queue; no model or network work runs in its real-time callback.

Playback assessments ask separate directedness, floor and readiness questions in one Jev request. A positive directed floor decision stops generation and drains queued audio immediately. An unfinished correction stays captured without a Talker input. A ready final correction enters the existing spoken revision/scope path once, with exact observed words. Its Hub scope hold is recorded synchronously before waiting for generation interruption; unfinished floor-only speech creates no scope hold. Complete directed Follow-up speech can be ready without requesting a playback stop. A voice-only stop creates no Task and cancels none. Background speech, Backchannels, quoted controls, uncertain labels and failed requests preserve output. Source keys bind results to observed revisions; typed replacement, retired epochs and changed words reject obsolete decisions.

The controller permits one request in flight and coalesces later snapshots. Silence is reassessed every 400 ms only while a talking period exists. Bounds are four captured sources, the existing 6,000-character request limit, 6,000 JSON context characters a 30-second period and at most 80 assessments per period. Failed observations stop silence-only retries; new source observations can reassess. The independent retention deadline remains active during an outage, and expired source identities and their late tails stay rejected. Exceeding a bound rejects the source and reports recovery; a rejected source's tail cannot become a fresh request. There is no idle conversational polling. These are provisional engineering safety bounds, not qualified conversational thresholds.

Jev is pinned to `jev-1.14.0`. Each request has a 700 ms HTTP timeout, a 750 ms total adapter deadline and no retries; the controller has an 800 ms outer deadline. Labels, finite probabilities, their sum and winning label, confidence, returned model and nonnegative integer token usage are checked. Both winning probability and confidence must reach 0.8 for a positive label. Usage records contain model, snapshot identity, token counts and duration, with no transcript or key. Provider failures appear as unavailable recognition, never as a successful negative classification.

The [official model documentation](https://docs.typesafe.ai/models) checked on 2026-11-06 lists Jev 1.14, text inputs, 64k request/32k question context, input pricing of $0.042 per million tokens and organization-specific token/request rate limits. The [System One contract](https://docs.typesafe.ai/api/system-one) defines named Choice questions, confidence, probabilities and usage. The [error reference](https://docs.typesafe.ai/api/errors) defines authentication, throttling and overload responses. Pumpkit's wrapper supplied the HTTP port/fake pattern; its settings, error classes and five-second/two-attempt policy were not imported. Account model access and actual limits require an explicitly bounded live evaluation.

Fake Hub cases establish the positive pre-endpoint stop path, source correction without duplicate words, voice-only Task preservation, negatives, latest-snapshot coalescing, silence reassessment and typed stale-result rejection. Adapter replay records per-inference duration and audio length for measuring scheduling; fake timings cannot qualify Parakeet throughput, accuracy, memory, Jev recognition or physical stop latency. Ticket #73 extends initial listening and thinking readiness, documented in [complete-thought readiness](complete-thought-readiness.md). Ticket #74 owns remaining lifecycle races, #75 owns independent keyboard/outage control, #77 owns wake qualification and #76 owns integrated independent confirmation. No real-provider calls, audio-device runs or credit use were performed for this implementation. Live development measurements must settle cadence/confidence/deadline tradeoffs before confirmation; these defaults are not User-approved acceptance numbers.
