# Natural-language Authorization with concrete, guarded Approvals

ADR 0013's closed vocabulary rejected "Yes, I approve" because of "I" and rejected the Hub's own deployment question because its description held several sentences and "no branches". It also required a new question even when the User had already requested the action. The User chose natural-language interpretation by the existing Talker, without another model turn.

The Talker interprets the current User message in conversation context and records Authorization through Hub tools. The Hub owns the original words and source identity. Authorization covers one action, a Task, or explicitly the session, including conditions and exclusions. A direct action instruction grants action scope; unattended work defaults to Task scope. Task permission persists across restarts until the Task ends or permission is revoked. Session permission covers current and future Tasks, ends at Hub restart, and never becomes persistent Task permission. Material changes invalidate affected Task permission; routine refinements preserve it through the Talker's explicit scope decision.

The Orchestrator judges whether an Authorization covers a concrete action and verifies its conditions. The Hub validates the Authorization's identity, state, Task and revision. Every consequential action still has a single-use Approval with its target and 24-hour expiry. The Hub executes merges and branch deletes through the existing target checks; other actions receive the same constrained Subagent grants. Revocation is checked after awaited target reads, at dispatch and before Subagent tool calls. Calls already underway cannot necessarily be stopped or undone.

When permission is missing, the Talker registers the pending Approval it will present and asks naturally. Only a completed reply commits presentation. The Talker interprets replies by meaning; the Hub no longer parses the reply or question against lexicons. It still refuses background turns and missing, expired, withdrawn or unpresented Approvals. A restart loses presentation context, so an ambiguous bare yes requires the action to be presented again; explicit new permission can instead be recorded as Authorization.

This supersedes the language-matching and every-action-question decisions in ADRs 0004 and 0013. Deterministic code enforces provenance and execution boundaries, not the meaning of language. A model can misinterpret permission or coverage; tests with fake agents prove the Hub contract, not model understanding. Runtime examples cover negation, conditions, scope limits, ambiguity and quoted permission. Real-model checks remain opt-in.
