# Resolve Task scope after local spoken admission

A spoken request keeps its generation identity and ordered raw segments when speech resumes after its first transcript reached the Talker. Its revision increases. A local floor decision admits speech or stops only the reply; an experimental amend/new_request label is a nonbinding hint. It cannot erase the opening, choose a Task or rewrite the User's words. The already-admitted Talker interprets the full source history and prior Task context.

The input pipeline stamps turns with a capture epoch, candidate sequence and actual VAD onset separately from retained pre-roll. Thinking-origin speech survives reply startup. Wake, typed replacement and shutdown retire the epoch. Reply callbacks carry generation identity/revision. Delayed onset delivery is interpreted against the owned reply's logical start/completion history; it does not become post-reply speech merely because delivery was late. Candidate played_text is the current queue/progress estimate at assessment start, not an onset snapshot or physical hearing measurement.

Confirmed unrelated fragments are discarded. Uncertain fragments are reassessed in order with later observed speech, keeping the earliest logical onset metadata. A newer known onset or transcript makes an in-flight partial decision obsolete. The full assessed source is retained; no unobserved future speech is inferred. The existing bounds are four retained/waiting/in-flight microphone fragments and a 6,000-character spoken request. A duration-limited run is reported and cannot admit its leftover tail as a fresh request. Future grounded recognizers must explicitly validate which observed raw segments are admitted; unselected background cannot ride into a conversational call. No failed research model is wired.

Before awaiting obsolete-generation interruption, VoiceMode synchronously records a locally admitted revision with the Hub. A pending spoken scope atomically retains raw speech and holds authority on the Tasks already owned by that request. Task requests, producer revisions and Approval targets remain unchanged while scope is unresolved. Typed clarification is a distinct admitted source; it invalidates earlier resolver attempts and is retained with the spoken context rather than silently replaced by it.

The Talker's resolve_scope tool names the exact scope ID, revision and attempt. It chooses the complete affected set of owned Task IDs, a separate request starting at a validated raw source boundary, or preserve_tasks for a direct answer/additional work that leaves existing Tasks unchanged. Stale, malformed, conflicting and repeated choices are refused. Missing selection and a 30-second resolution timeout retain the durable hold and report that clarification is needed; neither is an implicit no-change decision. A later User turn receives the unresolved context under a fresh attempt.

Only selected Tasks change. Their accepted raw intent, producer revision, obsolete Approval withdrawal and producer cancellation commit in one synchronous save batch before awaited interruption or chosen work. Unselected Tasks keep their intent and exact Approval targets. A separate topic may reset the current semantic context only at its validated raw boundary; historical speech remains available in the bounded recent request history. The Hub keeps the latest 64 resolved scopes and every unresolved hold; existing Task words retain their own history. delegate uses selected task_id for existing work and explicit new_task=true for additional work. It cannot bypass an unresolved scope.

Hosted Task tools and Subagent pre-tool hooks wait for scope resolution and then recheck source revision. The SDK's existing synchronous Bash/MCP/Approval checks run after that wait, once; generic hooks skip names with an explicit guarded hook. on_failure=block and strict_mcp_config remain. Hub Approval actions check authority before and after reading the pinned target, and read it again if scope changed during the wait. An already-dispatched irreversible action cannot be undone by a later request.

Pending scopes, typed context, producer revisions and queued source identity survive restart. Held Task work cannot run old recovery plans first. The Hub gives the already-admitted pending context to an ordinary text-only Talker turn; resolution does not depend on a restarted VoiceMode owning the old generation. Obsolete prepared worktrees are cleaned without opening an agent session. Independent Tasks and genuine provider Usage limit/availability evidence retain their existing scheduling and presentation.

The mechanical ownership and Task-authority contracts described here are completed under #57, with [fake-Hub verification and limits](../notes/admitted-spoken-revisions.md). #38 retains its original natural-continuation acceptance criteria, including a working production admission path. No production local recognizer is selected or wired. Independent semantic accuracy, actual worker readiness/deadlines, engine coexistence and physical audio/STT validation remain pending. ADRs 0014 and 0015 retain their behavior and latency requirements; #26 and #38 remain open, as do #39/#40 semantic admission and interruption acceptance.
